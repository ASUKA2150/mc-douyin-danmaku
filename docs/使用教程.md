## 一分钟了解它在做什么

```
你的抖音直播间  ──►  模组启动的一个浏览器  ──►  游戏聊天栏
                        （替你去访问直播间）
```

模组不去破解抖音的接口，而是**另起一个独立的浏览器**打开你的直播间，
然后通过浏览器的调试接口「旁观」页面收到的弹幕数据。

这么做的好处很实在：**抖音的签名和风控全由浏览器自己处理**，
你不需要装 Node.js、不需要找签名脚本，也不需要登录（想看礼物才要）。

这个浏览器：

- 和你平时用的浏览器**完全隔离**（独立配置目录，不读你的浏览记录和登录状态）
- 窗口默认**挪到屏幕外**，眼不见为净
- 只在游戏里连着直播间的时候才跑

## 快速开始

### 第一步 · 装模组

先确认游戏是 **Minecraft 1.21.1**，然后下载对应加载器的 jar 放进 `mods` 文件夹：

| 加载器 | 文件 | 还要装什么 |
|---|---|---|
| Fabric | `douyin-danmaku-fabric-1.21.1-x.x.x.jar` | [Fabric API](https://modrinth.com/mod/fabric-api) |
| NeoForge | `douyin-danmaku-neoforge-1.21.1-x.x.x.jar` | 不用 |

模组是**纯客户端**的，服务端不用装。

### 第二步 · 确认有浏览器

模组需要一个 **Chrome 或 Edge**。一般电脑上都有，模组会自己找，
找不到才需要手动指定（见[配置文件详解](#配置文件详解)里的 `chromePath`）。

### 第三步 · 连接直播间

进游戏、进一个世界，然后：

```
/dy connect 123456789
```

`123456789` 就是你的直播间号，也就是网址 `https://live.douyin.com/123456789`
最后那串数字。**直接粘整条分享链接也行**，模组会自己解析。

第一次连接要等十几秒（浏览器冷启动 + 加载页面），然后就开始出弹幕了：

```
[抖音] [粉丝团5] 张三: 主播这个房子好漂亮
[抖音] 路人甲: 哈哈哈哈
```

### 第四步（可选）· 登录，为了看礼物

**抖音只向「已登录」的连接推礼物消息。** 游客能收到弹幕、进房、点赞，
但礼物一条都不会来。想看礼物就执行一次：

```
/dy login
```

在弹出的浏览器窗口里登录抖音，**然后关掉那个窗口**，再 `/dy connect`。

登录凭据存在浏览器配置目录里，**登录一次长期有效**，以后不用重复。

## 指令大全

所有指令都以 `/dy` 开头（`dy` = 抖音）。

### `/dy`

显示帮助。记不住指令的时候直接敲这个。

```
/dy
```

---

### `/dy connect <直播间号>`

连接一个直播间。

```
/dy connect 123456789
/dy connect https://live.douyin.com/123456789
/dy connect 看看这个 https://v.douyin.com/xxxxx/ 挺好玩的
```

**接受的输入格式**（后面两种会自动解析出房间号）：

| 你输入的 | 说明 |
|---|---|
| `123456789` | 纯数字房间号，最直接 |
| `https://live.douyin.com/123456789` | 完整直播间链接 |
| 一整段分享文案 | 里面含上面两种之一就行 |

**行为说明：**

- 会**自动停掉**当前连接，所以切换直播间直接再敲一次就行，不用先断
- 房间号会**自动存进配置文件**，下次启动还记得
- 连接需要十几秒（要启动浏览器、加载页面）

> 想看自己直播间有没有开播，可以直接**打开任意一个正在直播的房间**测试，
> 不需要是自己开的播。

---

### `/dy disconnect`

断开连接，并关掉那个浏览器。

```
/dy disconnect
```

退出游戏世界时也会自动断（免得在标题界面还在收弹幕）。

---

### `/dy status`

看当前状态。**出问题第一步就敲这个。**

```
/dy status
```

会显示四项信息：

```
[抖音弹幕] 状态：已连接直播间 123456789
[抖音弹幕] 数据源：CHROME，直播间：123456789
[抖音弹幕] 配置文件：E:\...\.minecraft\config\douyindanmaku.json
[抖音弹幕] 日志文件：E:\...\.minecraft\config\douyindanmaku.log
```

后两项特别有用——**要反馈问题的时候，把日志文件发过来就能定位。**

---

### `/dy login`

打开一个可见的浏览器窗口让你登录抖音。

```
/dy login
```

**为什么需要登录**：抖音的弹幕服务器只向已登录的连接推礼物，
游客收不到礼物。登录一次长期有效。

**操作步骤：**

1. 敲 `/dy login`
2. 等一两秒，会弹出一个浏览器窗口
3. 在里面登录你的抖音账号
4. **关掉那个窗口**
5. `/dy connect <直播间号>`

> 登录后是以「已登录观众」的身份旁观，不会用你的账号发任何东西，
> 也不需要额外授权。

---

### `/dy toggle <类型>`

快速开关某一类消息。**直播中改这个最方便**，不用去动配置文件。

```
/dy toggle gift      切换礼物消息
/dy toggle member    切换进房消息
/dy toggle like      切换点赞播报
```

**`<类型>` 接受的所有写法：**

| 类型 | 可用的写法 |
|---|---|
| 礼物 | `gift`、`礼物` |
| 进房 | `member`、`enter`、`进房`、`入场` |
| 点赞 | `like`、`点赞` |
| 弹幕 | `chat` |

敲完会立刻显示当前状态，比如：

```
[抖音弹幕] 礼物消息：已开启
[抖音弹幕] 点赞播报：已关闭
```

**改完会立刻存盘**，下次启动还是这个设置。

**实用场景**：观众突然开始刷礼物刷屏了，想先专心看弹幕：

```
/dy toggle gift      关掉礼物
...过一会儿想看了...
/dy toggle gift      再打开
```

---

### `/dy stats`

输出直播间统计字段的观测报告。**怀疑模组读错了数据时用它。**

```
/dy stats
```

**为什么需要这个**：抖音的统计消息字段号调整过，而且光看数字猜不出含义
（实测踩过：把「累计观看」当成了「累计获赞」）。这个命令把抖音实际推的
字段原样列出来，**并标出每个字段的变化趋势**，一看便知。

输出长这样：

```
[抖音弹幕] 收到的统计消息：
[抖音弹幕]   RoomUserSeq 收到 12 次
[抖音弹幕]   RoomStats 收到 15 次
[抖音弹幕]
[抖音弹幕] 各字段（一直在涨 的那个才可能是累计值）：
[抖音弹幕]   RoomUserSeq：
[抖音弹幕]     f3=2284 一直在涨（变了 2 次）
[抖音弹幕]     f7=63133 波动（变了 3 次）
[抖音弹幕]     f8="6万+" 没变过
[抖音弹幕]     f11="6.3万" 没变过
[抖音弹幕]
[抖音弹幕] 当前在线人数：2284 ｜ 本场模组收到的赞：350
[抖音弹幕] （注：抖音的弹幕通道里没有「累计获赞」数据，所以本模组不显示它）
```

**怎么读这份报告：**

| 看到什么 | 说明 |
|---|---|
| `没有收到任何直播间统计消息` | 抖音没推统计，在线人数也就拿不到 |
| `一直在涨` | 单调递增，是累计值（但**不代表它是获赞**） |
| `波动` | 时高时低，是瞬时值（在线人数就是这样） |
| `没变过` | 观察期间没变化 |

**用途**：如果你怀疑「在线人数不对」，把模组显示的数和直播间面板对一下，
再把这份报告贴到 issue 里，就能定位问题。

---

### `/dy reload`

从磁盘重新读取配置文件。

```
/dy reload
```

**什么时候用**：你在游戏外编辑了 `config/douyindanmaku.json`，
想让它立刻生效（不用重启游戏）。

> 如果改的是**连接参数**（比如 `source`、`chromePath`），
> 光 reload 不够，还要 `/dy disconnect` 再 `/dy connect`。

## 四种消息类型

模组能显示四种消息，各自的**默认开关不同**：

| 类型 | 默认 | 显示效果 |
|---|---|---|
| **聊天弹幕** | 开 | `[抖音] [粉丝团5] 张三: 你好呀主播` |
| **礼物** | 开 | `[抖音] [粉丝团7] 土豪乙 送出了 小心心 x3 x5` |
| **进房** | 关 | `[抖音] 游客丁 进入了直播间` |
| **点赞** | 关 | `[抖音] 张三 为主播点赞` |

**为什么进房和点赞默认关着**：人气高的直播间进房会刷屏、点赞更是高频事件，
逐条显示会把真正的弹幕淹掉。想看就用 `/dy toggle` 打开。

### 点赞的特殊之处

**点赞不是逐条显示的**，而是按人攒一波、停下来之后再报一次。原因是点赞太密集
（有人能一口气点几百下），逐条显示会刷屏。

具体规则：

- **攒 5 秒**：一个人开始点赞后，等他不点了就把这一波报出来 ——
  一口气点 100 下只会出**一条**消息
- **每人 30 秒冷却**：同一个人 30 秒内最多被播报一次，
  所以有人一直点也只会偶尔冒一条
- **拿不到昵称的点赞不单独播报**，只计入总数

最后一条是有意设计：抖音有些点赞消息不带「是谁点的」。如果那种也报一条，
就会和按人播报**重复**——表现成同一个直播间同时冒出两个不同的累计数，
看起来像 bug。

### 两个「累计赞数」不要搞混

模组里只有**一个**能用的累计数，而且它不准。另一个（抖音面板上的累计获赞）
**拿不到**，原因见下一篇。

| 占位符 | 是什么 | 准不准 |
|---|---|---|
| `%like.session%` | 模组自己把点赞增量加起来得到的 | 不准。只是「本次连接期间收到的量」，断线归零 |
| `%like.count%` | 这一波点了几个 | 准 |
| `%room.online%` | 直播间当前在线人数 | 准 |
| `%like.total%` | **已弃用**。早期版本用它显示「累计获赞」，但那个数其实是别的东西 | 不要再用 |

**默认模板只用 `%nick%`**，不显示任何数字：

```jsonc
"likeFormat": "&7[&f抖音&7] &d%nick%&c 为主播点赞"
```

```
[抖音] 织柚zy 为主播点赞
```

**配色说明**：点赞用品红（`&d`）昵称 + 红色（`&c`）动作，
和聊天弹幕的青色区分开，一眼就能看出这条是点赞而不是弹幕。

**想要显示「这一波点了几个」**，自己在模板末尾加 `%like.count%`：

```jsonc
"likeFormat": "&7[&f抖音&7] &d%nick%&c 为主播点赞 &f+%like.count%"
```

```
[抖音] 织柚zy 为主播点赞 +30
```

### 为什么没有「累计获赞」

**抖音的弹幕通道里没有获赞这个数据。** 这不是「没找到字段」，是实测确认过的。

把统计消息里所有字段 dump 出来，能读出来的只有两种：

```
f3=2284  f7=63133  f8="6万+"  f9=2284  f10=2284  f11="6.3万"
```

- **在线人数**：`f3`、`f9`、`f10` 都是 2284
- **一个累计量**：`f7`/`f8`/`f11` = 63133 / "6万+" / "6.3万"

而当时**直播间面板上的获赞是 4 万**，和这个 6.3 万**对不上**。所以它不是获赞。

> 模组曾经把它当成获赞显示，结果是一个稳定错误的数字
> （面板 4 万、模组显示 6.3 万）。与其显示一个错的，不如不显示。

### 如果你还是想显示某个数字

有一个数是可以用的——**本场模组收到的赞**。但要知道它的局限：

- 它只是「**本次连接期间**收到的量」——断线重连会**归零**
- 断开期间观众点的赞，模组收不到
- 所以它**只会比真实值小**，而且不是面板上那个数

想显示就自己改模板：

```jsonc
"likeFormat": "&7[&f抖音&7] &d%nick%&c 为主播点赞 &8（本场 %like.session%）"
```

效果：

```
[抖音] 织柚zy 为主播点赞（本场 350）
```

**在线人数是可靠的**，也可以放进模板：

```jsonc
"likeFormat": "&7[&f抖音&7] &d%nick%&c 为主播点赞 &8（在线 %room.online%）"
```

```
[抖音] 织柚zy 为主播点赞（在线 2284）
```

数字过万会自动换算，念起来更自然：

```
520       → 520
9999      → 9999
10000     → 1万
25000     → 2.5万
1234567   → 123.5万
```

## 自定义显示样式

每种消息的显示格式都能改，配置项在 `chatFormat` / `giftFormat` /
`memberFormat` / `likeFormat` / `likeAnonymousFormat` / `systemFormat`。

### 颜色代码

用 `&` 加一个字母表示颜色，例如 `&b` 是青色。会被自动转成 Minecraft 的颜色代码。

| 写法 | 颜色 | 写法 | 颜色 |
|---|---|---|---|
| `&0` | 黑 | `&a` | 绿 |
| `&1` | 深蓝 | `&b` | 青 |
| `&2` | 深绿 | `&c` | 红 |
| `&3` | 深青 | `&d` | 粉 |
| `&4` | 深红 | `&e` | 黄 |
| `&5` | 紫 | `&f` | 白 |
| `&6` | 金 | `&7` | 灰 |
| `&8` | 深灰 | `&9` | 蓝 |

### 占位符

写在模板里，渲染时会被替换成实际内容。

**通用（四种消息都能用）：**

| 占位符 | 含义 |
|---|---|
| `%nick%` | 昵称 |

**弹幕专用：**

| 占位符 | 含义 |
|---|---|
| `%content%` | 弹幕正文 |

**用户信息（弹幕、礼物、进房、点赞都能用）：**

| 占位符 | 含义 |
|---|---|
| `%level.value%` | 抖音消费等级的数字 |
| `%fanclub.level%` | 粉丝团等级数字 |
| `%fanclub.name%` | 粉丝团名称 |

> 注意要写完整：是 `%level.value%` 而不是 `%level%`，
> 是 `%fanclub.level%` 而不是 `%fanclub%`。没有简写形式。

**礼物专用：**

| 占位符 | 含义 |
|---|---|
| `%gift.name%` | 礼物名，例如「小心心」 |
| `%gift.count%` | 这一波送了几个 |
| `%gift.combo%` | 连击数，形如 `x5`（连击数 ≤1 时为空白） |
| `%gift.diamond%` | 单价（抖币） |

**点赞专用：**

| 占位符 | 含义 |
|---|---|
| `%like.count%` | 这一波点了几个 |
| `%like.session%` | 本场模组收到的赞（断线会归零，只少不多） |
| `%like.total%` | **已弃用**，别用（早期用来显示一个错的数） |
| `%room.online%` | 直播间当前在线人数（可靠） |
| `%room.watched%` | 那个含义不确定的累计量（抖音没给标签，**实测和获赞对不上**，一般别用） |

**进房专用：**

| 占位符 | 含义 |
|---|---|
| `%member.count%` | 当前直播间人数 |

**模组提示专用：**

| 占位符 | 含义 |
|---|---|
| `%content%` | 提示正文 |

### 条件块（避免空括号）

语法：`%?条件:内容%` —— **条件成立才显示这一段**，不成立时连里面的
颜色代码一起消失。

**为什么需要它**：如果直接写 `[%fanclub.level%]`，遇到不是粉丝团的观众
就会在聊天栏留下一对空方括号 `[]`，很难看。

**可用条件：**

| 条件 | 成立的含义 |
|---|---|
| `fanclub.isMember` | 是粉丝团成员 |
| `fanclub.isSet` | 同上（别名） |
| `fanclub.isNew` | 粉丝团等级为 1（刚加入） |
| `level.isSet` | 取到了消费等级 |
| `gift.isCombo` | 礼物是连击（连击数 > 1） |
| `gift.isRepeatEnd` | 连击结束了 |
| `kind.isChat` | 这条是弹幕 |
| `kind.isGift` | 这条是礼物 |
| `kind.isLike` | 这条是点赞 |
| `kind.isMember` | 这条是进房 |

> 条件名字写错了**不会报错**，只是那段不显示。所以写错的话你会看到
> 那部分内容「消失」而不是报错。

### 现成的模板示例

**只显示粉丝团等级，不显示消费等级**（默认就是这个）：

```jsonc
"chatFormat": "&7[&f抖音&7] %?fanclub.isMember:[&d粉丝团%fanclub.level%&7] %&b%nick%&7: &f%content%"
```

效果：

```
[抖音] [粉丝团5] 张三: 你好
[抖音] 路人甲: 哈哈
```

**消费等级和粉丝团都显示：**

```jsonc
"chatFormat": "&7[&f抖音&7] %?level.isSet:[&eLv.%level.value%&7] %?fanclub.isMember:[&d粉丝团%fanclub.level%&7] %&b%nick%&7: &f%content%"
```

**只显示消费等级：**

```jsonc
"chatFormat": "&7[&f抖音&7] %?level.isSet:[&eLv.%level.value%&7] %&b%nick%&7: &f%content%"
```

**什么都不显示，只要昵称和正文：**

```jsonc
"chatFormat": "&7[&f抖音&7] &b%nick%&7: &f%content%"
```

**换昵称颜色**（把 `&b` 换掉，比如 `&e` 黄色、`&a` 绿色）：

```jsonc
"chatFormat": "&7[&f抖音&7] %?fanclub.isMember:[&d粉丝团%fanclub.level%&7] %&e%nick%&7: &f%content%"
```

> **注意：不要把 `%nick%` 后面的 `&7` 和 `&f` 删掉。**
> `&7` 是冒号的灰、`&f` 是正文的白——颜色代码会一直影响到后面，
> 少了它们正文会变成昵称的颜色，整行一个色就分不清谁在说话了。

**礼物里也带上粉丝团等级：**

```jsonc
"giftFormat": "&7[&f抖音&7] %?fanclub.isMember:[&d粉丝团%fanclub.level%&7] %&b%nick%&7 送出了 &e%gift.name% &7x&f%gift.count%%gift.combo%"
```

**礼物带单价：**

```jsonc
"giftFormat": "&7[&f抖音&7] &b%nick%&7 送出了 &e%gift.name% &7x&f%gift.count% &7(%f%gift.diamond%&7 抖币)"
```

## 配置文件详解

位置：`.minecraft/config/douyindanmaku.json`（`/dy status` 会告诉你确切路径）

第一次启动游戏后自动生成。改完在游戏里 `/dy reload` 生效。

### 连接设置

| 配置项 | 默认 | 说明 |
|---|---|---|
| `autoConnect` | `false` | 进世界后是否自动连接 |
| `room` | `""` | 直播间号。`/dy connect` 会自动写这里 |
| `source` | `"CHROME"` | 数据源，见下方说明 |

**`source` 的三个可选值：**

| 值 | 说明 |
|---|---|
| `"CHROME"` | **默认**。用浏览器旁观，不需要任何额外准备 |
| `"DIRECT"` | 模组自己连抖音弹幕服务器。省资源，但要自备签名脚本 |
| `"TCP"` | 等外部程序把弹幕转发过来（兼容 BakaDanmaku 的 tcp 模式） |

### 浏览器设置

| 配置项 | 默认 | 说明 |
|---|---|---|
| `chromePath` | `""` | Chrome/Edge 的完整路径。留空自动查找（先 Chrome 后 Edge） |
| `chromeProfileDir` | `""` | 浏览器配置目录。留空用游戏目录下的 `douyin-danmaku-browser` |
| `chromeOffscreen` | `true` | 是否把浏览器窗口挪到屏幕外 |
| `chromeWindowSize` | `"1280,800"` | 窗口尺寸 |

**关于 `chromeProfileDir`**：这个目录存着**登录状态**，所以要固定。
如果你把它删了，登录会失效（需要重新 `/dy login`）。

### 直连模式（`DIRECT`）才需要的

| 配置项 | 默认 | 说明 |
|---|---|---|
| `signScriptPath` | `"sign/sign_runner.js"` | 签名脚本路径，相对游戏目录 |
| `nodePath` | `""` | node.exe 路径，留空用 PATH 里的 |

> 只有把 `source` 改成 `"DIRECT"` 才需要这两项。默认的浏览器模式用不到。

### 显示设置

| 配置项 | 默认 | 说明 |
|---|---|---|
| `chatFormat` | 见上文 | 弹幕模板 |
| `giftFormat` | 见上文 | 礼物模板 |
| `memberFormat` | 见上文 | 进房模板 |
| `likeFormat` | 见上文 | 点赞模板（有昵称时） |
| `likeAnonymousFormat` | `""` | 点赞模板（**拿不到昵称时**）。空字符串 = 不显示 |
| `systemFormat` | `"&8[&b抖音弹幕&8] &7%content%"` | 模组自己的提示（连接成功/失败等）的模板 |
| `ensureChat` | `true` | 弹幕是否占聊天栏显示位置。改 `false` 就只进聊天记录 |
| `keepHistory` | `true` | 弹幕是否写进聊天记录（按 T 打开的那个界面） |
| `showUserLevel` | `true` | 是否显示消费等级（配合 `%level.value%` 用） |
| `showFanClub` | `true` | 是否显示粉丝团（配合 `%fanclub.level%` 用） |
| `stripEmoji` | `true` | 是否去掉 emoji（MC 字体画不出彩色 emoji，会显示成方框） |

### 消息类型开关

对应 `/dy toggle` 指令。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `showGift` | `true` | 显示礼物 |
| `showMember` | `false` | 显示进房 |
| `showLike` | `false` | 显示点赞播报 |

### 过滤设置

| 配置项 | 默认 | 说明 |
|---|---|---|
| `filterMode` | `"DISABLED"` | `DISABLED` 不过滤 / `BLACKLIST` 黑名单 / `WHITELIST` 白名单 |
| `filterKeywords` | `[]` | 关键词列表，例如 `["广告", "加群"]` |
| `blockedUsers` | `[]` | 屏蔽这些人的弹幕（精确匹配昵称，忽略大小写） |
| `maxDanmakuPerSecond` | `0` | 每秒最多显示几条，`0` = 不限制 |

**关键词过滤只对弹幕生效**——礼物名、进房这些不是用户自由输入的内容，
拿弹幕的屏蔽词去套会误伤。

**`maxDanmakuPerSecond` 建议**：热门直播间弹幕刷得快，设成 `10~20`
能明显减少掉帧。超出的弹幕会被丢掉——直播场景下丢几条不影响观看，
但掉帧主播和观众都能立刻感觉到。

### 高级：抖音协议字段号覆盖

**正常情况下全部保持 `-1` 不要动。**

| 配置项 | 默认 | 说明 |
|---|---|---|
| `userLevelOverride` | `-1` | User.pay_grade 的字段号 |
| `userLevelIconOverride` | `-1` | 等级图标的字段号 |
| `fansClubOverride` | `-1` | User.fans_club 的字段号 |
| `fanClubLevelOverride` | `-1` | FansClubData.level 的字段号 |
| `nickNameOverride` | `-1` | 昵称字段号 |
| `chatContentOverride` | `-1` | 弹幕正文字段号 |

`-1` 表示「用内置默认值」。**0 是合法的字段号，所以不能拿 0 当「没设置」。**

**什么时候需要改**：如果哪天发现「等级显示不出来」或者「昵称是空的」，
而弹幕本身正常，说明抖音调整了 protobuf 字段号。这时把对应项改成新字段号
即可，**不用等模组更新**。字段号可以去
[DouyinLiveWebFetcher](https://github.com/saermart/DouyinLiveWebFetcher)
的 `protobuf/douyin.py` 里查。

## 出问题了怎么查

### 第一步永远是 `/dy status`

它会告诉你当前状态、用的哪种数据源、配置文件在哪、日志文件在哪。

### 第二步看日志文件

```
.minecraft/config/douyindanmaku.log
```

**要反馈问题的话，直接把这个文件附上。** 它记录了：

- 浏览器启动的完整过程（路径、配置目录、调试端口）
- **浏览器自己的输出**（启动失败时它会说明原因）
- 收到的消息类型，以及**收到帧 / 解码 / 派发事件的计数**——
  一眼就能看出是「压根没收到」还是「收到了但解不出来」
- 统计消息的字段清单

### 日志里的关键词

| 看到这个 | 说明 |
|---|---|
| `运行状态：收到帧 X，已解码 Y，派发事件 Z` | 每分钟一条。数字都在涨就是正常 |
| `注意：一帧都没收到` | 连上了但浏览器没推数据，多半是页面被冻结或已下播 |
| `注意：收到了帧但没派发出任何事件` | 数据进来了但解不出来，请附日志提 issue |
| `聊天弹幕解码失败：...` | 抖音改了字段号，提示里会说明是哪个字段 |
| `[浏览器] ...` | 浏览器自己的输出，启动失败的原因通常在这 |
| `浏览器进程已启动，pid=...` | 启动成功 |
| `浏览器调试端口就绪：...` | 端口拿到了 |
| `浏览器把启动转交给了已在运行的实例` | 有残留的浏览器占着配置目录（不一定是错误） |
| `清掉了上次残留的调试端口文件` | 正常，上次没退干净，这次自动修好了 |
| `收到直播间统计：在线 X，累计量 Y` | 拿到直播间数据了 |
| `在线人数更新为 Z` | 正常 |
| `统计消息字段清单` | 排查字段用，也可以直接 `/dy stats` |
| `收到未处理的消息类型：...` | 抖音上了新消息类型（一般无害） |

## 常见问题

### 连不上 / 一直提示重连

按这个顺序查：

1. **敲 `/dy status`**，看它说当前是什么状态
2. **翻日志文件里 `[浏览器]` 开头的行**，启动失败的原因通常在那
3. **那个直播间是不是没开播？** 没开播的房间不会有弹幕通道
   （顺带也能验证你房间号填对没有）
4. **找不到浏览器？** 在配置里把 `chromePath` 填成完整路径
5. **第一次连接要等十几秒**——浏览器冷启动加加载页面，这是正常的

### 收不到礼物

**先 `/dy login` 登录抖音。** 抖音只向已登录的连接推礼物，
游客收不到。登录一次长期有效。

### 点赞完全不显示

点赞默认是**关的**，先打开：`/dy toggle like`。

打开后还是不显示，可能是拿不到「是谁点的」——抖音有些点赞消息是匿名的，
而匿名那部分**只计入总数、不单独播报**（不然会和按人播报重复）。

这种情况可以用 `/dy stats` 看收到的消息类型，确认抖音到底有没有在推点赞消息。
如果确认在推、但模组不显示，附上日志文件提个 issue。

### 想显示获赞 / 在线人数

**获赞拿不到**，原因见上文「为什么没有累计获赞」——抖音的弹幕通道里
压根没这个数据，显示一个错的比不显示更糟。

**在线人数可靠**，可以加进模板：

```jsonc
"likeFormat": "&7[&f抖音&7] &d%nick%&c 为主播点赞 &8（在线 %room.online%）"
```

也可以用 `/dy stats` 随时查当前状态。

### 等级/粉丝团不显示

多半是抖音调整了 protobuf 字段号。用配置文件里的
`userLevelOverride` / `userLevelIconOverride` / `fansClubOverride` /
`fanClubLevelOverride` 调整，不用重新编译。

### 弹幕里 emoji 变成方框

正常现象——Minecraft 的默认字体不含彩色 emoji。
配置里 `stripEmoji` 保持 `true` 会直接去掉它们。

### 弹幕太卡 / 掉帧

把 `maxDanmakuPerSecond` 设成 `10` 或 `20`。

### 全屏玩 Minecraft 会不会影响收弹幕

模组做了四层防护：关掉浏览器的省电行为、每 20 秒把页面钉在活跃状态、
模拟页面有焦点、断线自动重连。

如果还是遇到中途断连，把 `chromeOffscreen` 改成 `false`
让窗口留在桌面上（**不要最小化**——最小化会被系统更强地节流）。

### 换了直播间要不要删配置文件

**不用。** `/dy connect` 会自动停掉旧连接、写回新房间号。

配置文件只在两种情况下需要动：改设置，或者模组让你删（比如中文乱码那一类）。

### 会不会封号

模组**匿名旁观**你自己指定直播间的公开弹幕：不登录账号（除非你用 `/dy login`）、
不发送任何内容、不修改直播间数据。对抖音来说它就是一个普通观众在看直播。

但抖音的接口毕竟不是公开 API，**使用风险请自行判断**。建议只连自己的直播间。

## 附：数据源的选择

默认的浏览器模式对绝大多数人够用。如果你有特殊需求，另外两种模式是：

| | CHROME（默认） | DIRECT | TCP |
|---|---|---|---|
| 需要额外准备 | 不需要 | Node.js + 签名脚本 | 外部转发程序 |
| 内存占用 | 高（一个浏览器） | 低 | 最低 |
| 抗抖音改协议 | 强 | 弱 | 看转发程序 |
| 能收礼物 | 登录后可以 | 登录后可以 | 看转发程序 |
| 适合 | 所有人 | 机器吃紧、愿意折腾 | 手上有别的抓弹幕工具 |

`DIRECT` 模式需要自备签名脚本的原因：抖音要求连接时带一个签名参数，
而那个签名必须用抖音自己的混淆 JavaScript 算出来，纯 Java 做不到。
具体怎么准备见 [README 的附录](../README.md)（「DIRECT 模式」那一节）。
